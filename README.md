# Grand Line Ledger

A local-first tournament tracker for the **One Piece Trading Card Game**. Log every event, every round, and every dice roll — then see what actually works.

Built as an installable PWA with a mobile-first UI. No account, no server, no sync: everything lives in your browser's `localStorage`, and JSON backups are one tap away.

## Features

- **Tournaments** — name, date, format, location, notes, and the leader you registered.
- **Rounds** — opponent leader, optional opponent name, round number, who won the dice, who played first, game score (2–1, 2–0, draws), and notes.
- **Full leader search** — 138 bundled leaders (every OP/ST/EB leader in the public card data), searchable by name, set code, or colour, with colour filters and recently used leaders. Missing something? Add a custom leader.
- **Stats** — match and game win rates, matchup breakdown by opposing leader, results by your leader, and dice/turn-order splits. Filter by period and by your leader.
- **Backups** — export everything to JSON, import it back with a preview, or clear the ledger.
- **PWA** — install to a home screen, offline app shell, and cached leader art.
- **Smart defaults** — first player follows the dice winner until you override it; round numbers auto-increment; "Save & add another" keeps you in flow.

## Quick start

Requirements: [Bun](https://bun.sh) (Node/npm are not required).

```bash
bun install
bun run dev
```

Open the printed local URL. For a production build:

```bash
bun run build
bun run preview
```

The built app is in `dist/` and can be hosted on any static host (GitHub Pages, Netlify, Cloudflare Pages, etc.). Routing uses hash URLs, so no server rewrites are needed.

## Deploy to GitHub Pages

The repo includes `.github/workflows/deploy.yml`. It runs the unit tests and production build on every push and pull request, and deploys `dist/` when `main` is updated.

1. Push the repo to GitHub with `main` as the default branch.
2. In the repo, open **Settings → Pages → Build and deployment** and set **Source** to **GitHub Actions**.
3. Push to `main`, or run the workflow manually from the **Actions** tab.

The site will be published at `https://<user>.github.io/<repo>/`. No base-path configuration is required: Vite uses relative asset URLs and the app uses hash routing, so it works under any subpath. `dist/` is intentionally not committed — Actions builds and uploads it as the Pages artifact.

## Scripts

| Command | What it does |
| --- | --- |
| `bun run dev` | Start the Vite dev server. |
| `bun run build` | Type-check and build for production. |
| `bun run preview` | Serve the production build locally. |
| `bun run test` | Run the Vitest unit tests. |
| `bun run leaders` | Regenerate `src/data/leaders.json` from the public OPTCG API (needs network). |
| `bun run icons` | Rebuild the PNG PWA icons from the SVG sources. |
| `bun run test:e2e` | Playwright smoke test. Start `bun run dev --port 4173` first. |
| `bun run test:qa` | Playwright visual/behaviour QA pass with screenshots. |

The Playwright scripts are developer tools. Install the browser once with `bunx playwright install chromium` if you want to run them. `scripts/pwa-check.ts` (run with `bun run scripts/pwa-check.ts` against `bun run preview`) verifies the service worker, offline shell, and leader-art cache.

## Data & storage

- Storage key: `grand-line-ledger:data:v1`.
- Data shape: `{ version: 1, tournaments, matches, customLeaders }`.
- A match result is derived from the game score: more games won = win, fewer = loss, equal = draw. There is no separate result field, so the score is the single source of truth.
- The leader is set per tournament and inherited by its rounds.
- Importing a backup replaces the current ledger. Export first if you need a copy.
- Clearing site data deletes the ledger; keep a JSON backup somewhere safe.

Backups are portable between devices and can be edited by hand if needed. The importer validates the schema and reports the first problem it finds.

## Leader data

`src/data/leaders.json` is generated by `scripts/fetch-leaders.ts`:

- Card metadata comes from the public [OPTCG API](https://optcgapi.com).
- Leader art URLs point at the Limitless TCG card CDN. All 138 URLs were verified to return `200`.
- Alternate arts and reprints are deduplicated to one entry per card ID, preferring the base art.

The artwork is © Eiichiro Oda / Shueisha / Toei Animation and is used here for a personal, non-commercial tracker. This project is unofficial and not affiliated with Bandai or the One Piece TCG.

## Tech stack

- Vite 8, React 19, TypeScript
- Tailwind CSS v4
- React Router 7 (`HashRouter`)
- Zod for backup validation
- `vite-plugin-pwa` for the manifest, precache, and leader-art runtime cache
- Vitest for unit tests, Playwright for end-to-end checks
